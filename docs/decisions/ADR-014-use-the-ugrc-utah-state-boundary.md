# ADR-014: Use the maintained UGRC Utah state boundary

## Status

Accepted

## Date

2026-08-10

## Context

The maps and `in_utah` classification used a six-corner approximation of
Utah's nominal latitude and longitude lines. That shape captured the
northeast notch, but it did not capture the surveyed variation visible
against modern basemaps. It also left two definitions of Utah: a visual mask
in JavaScript and a classification ring in Python.

The Utah Geospatial Resource Center (UGRC) publishes the state boundary it
maintains with the Lieutenant Governor's Office. The service contains both a
Utah feature and an outside-state mask; the Utah feature is the reusable
source because it supports the outline, inverse mask, and point-in-polygon
classification.

## Decision

Commit `utah-boundary.geojson`, generated by
`scripts/fetch-utah-boundary.mjs` from the UGRC Utah State Boundary feature.
Request WGS 84 output and generalize to `0.0001` degrees (about 10 metres at
Utah's latitude). The resulting 307-vertex, 7 KiB polygon is far more precise
than the dashboard can display while remaining inexpensive on a phone.

Use this one polygon for all three map masks and for Python's `in_utah`
classification. Copy it into both the root and `data/` paths in the published
artifact, following ADR-002.

## Alternatives considered

### Keep the six-corner approximation

Rejected. It is compact, but visibly disagrees with basemaps and is not an
appropriate boundary for scientific classification near a state line.

### Fetch UGRC at page load

Rejected. A third-party outage would change the map and the boundary could
move independently of the versioned classification.

### Use the service's precomputed mask feature

Rejected as the sole source. It draws the inverse mask efficiently but cannot
also answer whether a point is inside Utah. Keeping the Utah polygon avoids
two boundary sources.

## Consequences

- The browser falls back to the six-corner visual mask if the local context
  file is missing, so reservoir data remains usable. Smoke tests require the
  authoritative 307-point geometry in normal builds, preventing a silent
  permanent fallback.
- The Python pipeline does not fall back: a missing committed boundary fails
  loudly rather than publishing classifications from a less accurate shape.
- Rebuilding the boundary is an intentional maintainer action. The fetch
  script refuses to write unless the filtered service response contains
  exactly one polygon or multipolygon.
- Cross-border waterbodies remain governed by ADR-013. A dam point outside
  Utah does not prove that the reservoir surface is outside Utah.
